# ASO plan — Play listing, metadata and discovery (2026-11-19)

> **Status:** draft v1, under Qiyas Council review. The listing copy lives in
> [`store-listing.md`](store-listing.md); this file owns the discovery strategy — keywords, title/short
> description rules, category/tags, screenshots, experiments, web SEO and the checks that must pass
> before the copy is pasted into Play Console. Every claim here is either measured in the workspace or
> marked as an assumption.

## 1. Why this pass exists

The current listing was written for **honesty** (every claim verifiable) but not for **discovery**:
title "Sigha: File Converter" (21/30), short description "Convert files on your phone. No upload, no
account, no ads." (59/80), and a full description that leads with the product name rather than with
the words people search for. Play ranks a listing on the title, the short description, the full
description, the developer name, and on install/retention/rating signals — not on a hidden keyword
field. So the words in the title and the first lines of the description are the whole keyword surface.

## 2. Evidence gathered (2026-11-19, IQ storefront)

Method: `google-play-scraper` 10.1.4 search + autocomplete against play.google.com, country `iq`;
App Store iTunes Search API for the name check. Search APIs are fuzzy; counts below are the returned
result sets, not the whole store.

| Query | What ranks today | Read |
|---|---|---|
| `file converter` | File Converter (com.onlineconvert.ocapp), File Converter (icecoldapps), Image to PDF, File Converter - All Formats, 9xConvert | the exact head term is contested by small apps rated 3.5–4.4 — a well-rated, Arabic-first entry can compete |
| `محول الملفات` | WPS Office, iLovePDF, PDF Reader/Editor apps, Image to PDF | Arabic intent is **PDF-heavy**; "محول الملفات" alone does not surface a general converter |
| `تحويل الملفات` | iLovePDF, WPS, PDF readers, Text to PDF | same; PDF tools own the Arabic head terms |
| `pdf converter` | Image to PDF - PDF Maker, PDF Converter: Scanner & Maker, CamScanner, WPS, iLovePDF | the PDF sub-intent is the biggest volume; our PDF edges (PDF→JPG/PNG/TXT, image→PDF) are real |
| `تحويل صيغة` | Video Converter, File Converter, Remux | mixed intent; format-conversion wording is weak |

Autocomplete (what people actually type):

| Seed | Suggestions |
|---|---|
| `file con` | file converter, file converter app free, file convert, file converter and compressor, file conveter |
| `file converter` | file converter, file converter app free, file converter and compressor, file converter avif tiff amv, file converter pdf |
| `محول` | محول الفيديو الى موسيقى mp3, محول الصور الى pdf, محول العملات, محول صور الى pdf, محول pdf |
| `تحويل` | تحويل الفيديو الى موسيقى, تحويل الصور الى pdf, تحويل الهاتف الى ايفون, تحويل الفيديو الى mp3 بدون انترنت |
| `docx` | docx, docx فتح ملفات, docx google, docx pdf, docx editor |

Two findings drive the plan:

1. **"app free" and "بدون انترنت" are typed by real users** — "no ads, no upload, free" is a genuine
   search phrase, not only a positioning statement. The app can prove all three.
2. **Arabic PDF intents are the volume** ("محول الصور الى pdf", "تحويل الصور الى pdf", "محول pdf"),
   and the app can serve them (image→PDF, PDF→JPG/PNG/TXT, DOCX/XLSX/TXT→PDF). The Arabic listing
   should therefore lead with PDF intents, not with the generic word "ملفات".

## 3. Keyword map

**English — primary (must appear in title/short/full):** file converter · PDF converter · image to
PDF · PDF to JPG · PDF to text · DOCX to PDF · HEIC to JPG · video to MP3 · audio converter · offline
file converter · no upload · free.
**English — long tail (full description and web FAQ):** convert XLSX to CSV, CSV to XLSX, SRT to VTT,
EPUB to text, ZIP converter, 7Z to ZIP, PNG to WebP, WebP to JPG, MKV to MP4, video to GIF, extract
audio from video, scanned PDF to text (OCR).
**Arabic — primary:** محول ملفات · تحويل الملفات · تحويل الصور الى PDF · تحويل PDF الى صور · PDF الى
نص · تحويل DOCX الى PDF · تحويل الفيديو الى MP3 · محول صوتيات · تحويل بدون انترنت · على هاتفك ·
واجهة عربية.
**Arabic — long tail:** تحويل HEIC الى JPG, تحويل XLSX الى CSV, تحويل SRT الى VTT, EPUB الى نص,
تحويل 7Z الى ZIP, استخراج الصوت من الفيديو, تحويل PDF الممسوح ضوئيًا الى نص.

Rules: one keyword phrase per sentence, no comma-stuffed lists (Play's spam policy and reviewers
dislike them), no competitor names, no "best/#1", no "every format". Every keyword must be true of
the shipped build; the 9 catalogue-only formats (TIFF, RTF, TAR, BZ2, XZ, YAML, XML, MOBI, FB2) never
appear as supported.

## 4. Title (30 chars max)

**Default-language (English) title: keep "Sigha: File Converter" (21/30).** Council round 1 was
split on adding "PDF": the Engineer and the Devil's Advocate both showed that "File & PDF Converter"
imports edit/merge/compress intent this build cannot serve (the app converts PDFs and to PDFs, but
does not edit, merge or compress them), and mismatched intent is the classic one-star engine. The
PDF head term moves to the short description instead. Candidates considered:

| Candidate | Chars | Verdict |
|---|---|---|
| **Sigha: File Converter** (current) | **21** | recommended for the default listing: brand + head term, no unserved intent |
| Sigha: File & PDF Converter | 27 | dropped: PDF edit/merge intent the build does not serve |
| Sigha: Converter & PDF Tools | 28 | dropped: "tools" implies a suite |
| Sigha: Offline File Converter | 29 | dropped: the OCR pack download makes "offline" a policy argument |
| Sigha: On-Device File Converter | 31 | over limit |

**Arabic localized title: "صيغة: محوّل ملفات على هاتفك" (27/30).** Council round 2 voted the PDF
token out of the Arabic title too (Devil's Advocate, Policy Guardian; Expert preferred the shorter
"محوّل ملفات و PDF", Arabic-First Editor argued for the PDF/صور title): "محوّل PDF" is the
iLovePDF/WPS edit-intent shelf, and the title is a claim channel, so it carries the honest
differentiator "على هاتفك" instead. The PDF and صور intents move to the Arabic short description as
explicit conversion pairs. The device label already reads صيغة in Arabic. Play Console store-listing
translations carry the app name per locale — confirm the field is present in the console before
relying on it, and keep the device label and the listing titles from contradicting each other.

**Dissents recorded:** Arabic-First Editor holds that the Arabic market's typed head terms are
PDF-framed ("محول الصور الى pdf" is in the measured autocomplete) and that the Arabic title should
carry PDF; the short description's outcome pairs are the mitigation. Revisit after the closed test
with real search-term data from Play Console.

## 5. Short description (80 chars max)

**English (71/80) — outcome pairs, exact-direction matching:**
```
Image to PDF, PDF to text, DOCX to PDF, video to MP3 — free, no upload.
```
Why: each phrase is a shipped edge and a winnable long-tail (round-1 keyword map). "Free" is a typed
suggestion in the Play autocomplete ("file converter app free"), "no upload" is the trust hook
against the web tools, and the four pairs beat a category opener that fights iLovePDF/WPS on head
terms. "No ads"/"no account" stay in the full description and in the ads declaration.

**Arabic (79/80) — the same four pairs, singular "صورة", typed gerund first:**
```
تحويل صورة إلى PDF، وPDF إلى نص، وDOCX إلى PDF، وفيديو إلى MP3. مجاني، دون رفع.
```
Why: the Arabic autocomplete is verb-first ("تحويل الصور الى pdf", "تحويل الفيديو الى mp3"), so the
field opens with **تحويل**; singular "صورة" (not "الصور") avoids promising many-images-to-one-PDF,
which 0.2.1 does not ship; "مجاني، دون رفع" mirror the English claims and the Data-safety answers.
The v2 generic line ("تحويل الملفات والصور إلى PDF…") was dropped: it repeated the title's head term
and did not carry the three other outcome pairs.

## 6. Full description (4,000 chars max)

Structure, in order — the first two lines are what the listing shows before "read more":

1. **Hook (2 lines):** the four outcomes people search, as nouns the query contains, then the
   privacy proof.
   EN: "Convert images to PDF, pull the text out of a PDF, turn DOCX into PDF or a video into MP3 —
   on your phone, without uploading anything."
   AR: "تحويل الصور إلى PDF، واستخراج النص من PDF، وتحويل DOCX إلى PDF أو الفيديو إلى MP3 — على
   هاتفك، دون رفع أي ملف."
2. **WHAT YOU CAN CONVERT** — grouped by intent, not by engine family, each bullet a searchable pair
   (image → PDF, PDF → JPG/PNG, PDF → text, DOCX → PDF, XLSX → CSV, CSV → XLSX, TXT/Markdown → PDF,
   HEIC/AVIF → JPG, any image → PDF, MP3/M4A/AAC/WAV/FLAC/OGG/OPUS interchange, video → MP4/WebM/MKV/GIF,
   extract audio, SRT ↔ VTT, EPUB → text/HTML, ZIP/TAR.GZ repack, 7Z → ZIP). No format counts
   ("48 formats", "32 converters") — counts date badly and invite "where is X?" reviews.
3. **BUILT FOR ARABIC** — full Arabic interface, RTL, Arabic OCR pack, Arabic privacy policy.
4. **PRIVATE BY DESIGN** — on-device conversion, no account, no ads, no analytics, no tracking SDK.
   The "no upload" line must carry its exception in the same block: "the only network request is
   the OCR pack you start yourself (28 MB)". Never the absolute "no network requests".
5. **HONEST LIMITS** — office layout not preserved, scanned PDFs need the OCR pack (English/Arabic),
   **no PDF editing, merging, splitting or compression**, no RAR, no 7Z creation, no target-size
   compression, HEIC needs Android 9+, AVIF Android 12+. This block is the trust engine: it must
   stay in every version. Two sentences move up beside the first PDF claim, **before the read-more
   fold** (first ~300 characters), not only into this block: the no-edit/merge/split/compress
   sentence, and the scanned-PDF/OCR precondition (Devil's Advocate and Policy Guardian round 2:
   "PDF to text" otherwise reads false to exactly the users most likely to install).
6. **REQUIRES ANDROID 8.0+** and the Download/Sigha destination.

Banned wording in every locale: "offline" as an absolute, "100% safe/secure", "no data collected"
without the policy's IP disclosure, "best", "#1", "every format", "all formats", competitor names,
format counts, and any merge/split/compress/edit promise.

Production-only edit: the "Version 0.2.1 is a closed-test build…" paragraph is deleted before the
production listing (it is true only during the closed test). The HONEST LIMITS block stays forever.

## 7. Category and tags

- **Category: Tools.** Not Productivity: the app is a utility with a single job, and Tools is where
  the "file converter" competitors sit. Productivity invites comparison with WPS/Office suites.
- **Tags** (Play Console → Store presence; select up to 5 from the console list, exact labels depend
  on the console): file management, utilities, PDF, documents. Do **not** pick an "offline" tag while
  the OCR pack downloads — the tag would contradict the policy line. Confirm in the console; tags
  are a discovery aid, not a ranking guarantee.
- **Content rating:** Everyone / utility answers (no ads, no UGC, no data sharing).
- **Target audience:** 13+; the app has no child-directed features.

### Listing parity gate

A promise that exists in one locale and not the other is a policy defect (the store-listing parity
rules, `store-listing.md` §2). The check is mechanical, not a review:

1. Every title/short/full field ≤ its Play limit, computed, not eyeballed (title 30, short 80, full
   4,000, release notes 500).
2. The EN and AR fields carry the same claim set: the same outcome pairs, the same proofs, the same
   limits. A claim only in one locale is a finding.
3. The banned-wording list in §6 is checked in both locales.
4. The typed head terms in §2 appear in the title, short or first 300 characters of the full
   description — where Play's matching actually looks — and nowhere do they contradict the build.

**Builder follow-up (0.2.2 tooling):** extend the claim-drift step in `scripts/verify.ps1` (currently
EN↔AR source strings) to these listing fields so drift fails the gate instead of relying on a human
read. Until then the checklist in `store-listing.md` §9 is the gate.

Feature graphic (1024×500): brand + "Convert files on your phone." + a four-icon row (PDF, DOCX,
image, video) + the Arabic tagline "حوّل ملفاتك على هاتفك". No device mockup of a feature that does
not exist. Promo video: optional, skip for the closed test.

## 9. Web SEO (the part Play does not do for you)

Play listings rank in Google search, but a domain you control is the only place to own the long tail
and the legal pages:

1. **Domain** (e.g. `sigha.app`): landing page, privacy policy, LGPL source page. One domain serves
   B2 (privacy URL), B6 (source hosting) and this section. Check availability before naming it in any
   document; if the name changes per B5, the domain changes with it.
2. **Landing page** (EN + AR, hreflang): H1 "Sigha — file converter for Android, on your phone";
   sections per intent (image to PDF, PDF to text, DOCX to PDF, video to MP3), each with a 2-line
   explanation and the honest limit; FAQ (does it upload files? no; does it work offline? conversions
   do, the OCR pack is a download; is it free? yes, no ads).
3. **Structured data:** `SoftwareApplication` JSON-LD (name, operatingSystem "Android", 
   applicationCategory "UtilitiesApplication", offers price 0, downloadUrl Play link) and `FAQPage`
   for the FAQ block. This is what can produce a rich result for "sigha file converter".
4. **Privacy page** must be the same text as the in-app asset, indexable, HTTPS, no login (B2).
5. **Search Console** after the domain exists: submit sitemap, check indexing of the privacy page and
   the FAQ.
6. Link the site in Play Console → Store listing → Website, and in the app's About screen (already
   links the privacy policy; add the site when it exists).

## 10. Experiments and measurement (after the closed test)

- Play **store listing experiments** can A/B the icon, feature graphic, screenshots, short and full
  description (title is not testable). Run one variable at a time for at least 7 days or until
  significance; start with the short description (EN) then the first screenshot.
- Metrics that matter: store-listing visitors → installs (Play Console), keyword rank for the 10
  primary terms (manual check, same storefront/device), day-1/day-7 retention, crash-free sessions.
- Decision date: two weeks after production rollout; keep or revert per experiment.

## 11. What NOT to do

- No keyword stuffing, no competitor names, no "best/#1/every format", no emoji walls.
- Do not list the 9 catalogue-only formats as supported; do not promise layout fidelity, RAR, 7Z
  creation, merge/split/compress or target-size compression — none ship in 0.2.1.
- Do not test the title with an experiment (not supported); do not change the title after the first
  upload without checking B5 (the name may be forced to change before upload, never after).
- Do not paste any copy into Play Console before the gate in `store-listing.md` §9 passes.
