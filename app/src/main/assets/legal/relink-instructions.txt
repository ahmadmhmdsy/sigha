REPLACING THE NATIVE LIBRARIES — RELINK AND INSTALLATION INFORMATION

The LGPL gives you the right to modify the library components and to run the app
with your modified version. Sigha loads the FFmpeg libraries as shared objects
from the APK's native library folders:

  lib/arm64-v8a/libavcodec.so, libavformat.so, libavfilter.so, libavutil.so,
  libswresample.so, libswscale.so, libavdevice.so, libffmpegkit.so,
  libffmpegkit_abidetect.so
  (and the same set under lib/x86_64/)

To replace them with your own build:

  1. Request the Corresponding Source using the written offer in this app, or use
     the published source archive when available. Obtaining the source is free.
  2. Build the libraries for the same Android ABIs (arm64-v8a and x86_64) and
     keep the same file names and a compatible public interface; the app talks to
     FFmpegKit only through the documented com.arthenica.ffmpegkit API.
  3. Build an APK containing your libraries in place of the originals. The
     remaining code needed to rebuild and relink the app — its Gradle build
     files, the Kotlin/Java sources that call the library, and the packaging
     configuration — is part of the Corresponding Source offered to you.
     [PUBLISHER TODO — blocker B6/B7: confirm with counsel how the app-side
     relinkable material is delivered, and state it here. Until then this offer
     is incomplete for LGPL-3.0 section 4(d).]
  4. Sign the resulting APK with your own key and install it. Android only
     installs an APK whose signature matches the installed one, so to run a
     modified build you must first uninstall the store version (or use a build
     signed with the same key, which only the publisher has). This is a platform
     restriction; the publisher does not and cannot prevent you from building,
     signing and installing your own modified version for private use.

The publisher has not signed any device against modification and has not added
any technical restriction beyond Android's own signature requirement.
